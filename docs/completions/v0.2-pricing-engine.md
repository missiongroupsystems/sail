# v0.2 Pricing engine: completion note

Date: 4 Nov 2026. Branch: `feat/beta-v1`. Roadmap phase 2 (v0.1 → v0.2).

## What

The pricing pipeline from scope §4.8 as one pure function in `shared`: `price(order, rules, context) → { lines, adjustments, totals, trace, warnings, pricing_status }`. Fixed rule schema (kind, calc, fixed or open value, explicit level, scope with exclusions, the fixed condition set, cap, priority with ID tiebreak, stacking, auto/manual, role and reason flags, GST flag, reporting class, `disables` for the waiver). The seven steps: base prices with per-order-type prices and open prices; line-level discounts with exclusive/stackable; order-level discounts spread in proportion; fees with no compounding; GST per line in both tax modes; caps spread back; largest-remainder rounding. Freeze semantics (`freezeFrom`, `context.frozen`). Step-by-step trace. Pure validation warnings. Seed configuration (service charge, container deposit, six manual presets). A readable reference-set format with 91 hand-calculated cases, property tests, and a semantics note.

## How

- Integer cents throughout; percentages in basis points; `percentOfCents` rounds half up; GST inside an inclusive amount is `amount × rate / (1 + rate)` rounded half up.
- Every per-line spread (order-level discounts, caps, fixed-per-order fees) goes through `allocateLargestRemainder`, the same allocator bill splits and refunds use in v0.7, so "parts add up to the whole" is proven once.
- Determinism: rules sorted by `(priority, id)`, manual applications by `application_id`; property-tested against shuffled input.
- The reference set is written as arithmetic expressions with prose working, so Finance can check each case by reading it. The coverage test lists 41 feature tags that must all appear.
- The engine is the only place that computes amounts. The server (v0.4), the POS preview, the simulator (v0.3) and refunds (v0.7) all call it.

## Why

The pipeline is the critical path and the top correctness risk (scope §6). Proving it as a pure function before anything consumes it (roadmap §1, principle 1) means splits, refunds, receipts and reports read amounts that are already verified.

## Decisions needing confirmation (business choices, built with a documented default)

1. Minimum spend measured on undiscounted amounts.
2. Service charge in inclusive mode computed on GST-inclusive prices and itself GST-inclusive.
3. Exclusive discounts block everything evaluated after them on their lines (including order-level discounts).
4. "% off bill" preset is order-level (frozen at first payment).
5. Zero-amount manual applications are recorded as zero adjustments for audit.
