# Launchpad architecture (from Launchpad Engineer, 29 Oct 2026; main 42777e37)

1. Repo: pnpm 10 workspaces + Turbo, Node >=22.23. Packages server (Hono), web (Next.js), shared (zod schemas/types). Overrides/patches in pnpm-workspace.yaml (postgres@3.4.8 patch for socket-write crash).
2. Backend: src/app.ts separate from index.ts. CORS, AppError onError. Public /health /internal /bridge; /api behind authMiddleware -> rlsMiddleware; routes/*.ts per domain, services/*. Zod 4 validate() middleware, schemas in shared; no OpenAPI. Auth: Bearer Supabase JWT via JWKS (jose); Passport SSO second issuer, auto-provision; users row via supabase_id. DB: postgres.js on Supabase 6543 txn pooler, POOL_MAX sized to 57 conns; db is a Proxy over per-request txn in AsyncLocalStorage; rlsMiddleware: one txn per request via admission gate (TX_MAX 6, queue 64, then 503), set_config('app.current_*') + SET LOCAL ROLE app_authenticated, RLS reads those. RLS-bypass routes listed in rls-opt-out.ts with a test.
3. Migrations: drizzle-kit (public, passport, ops schemas). Always db:generate; for RLS/grants/seeds do a no-op schema edit, generate, replace SQL. db:migrate = drift check, migrate, drift check. Forward-only, straight to prod, no staging. Browser never uses PostgREST; Supabase is auth + storage only.
4. Realtime: no Supabase Realtime. Hono streamSSE fed by pg_notify triggers; LISTEN on separate 5432 session connection (test rejects 6543). Stream status resolved in short RLS txn first. Web uses fetch streaming (EventSource can't send Bearer). Collab (Hocuspocus/Yjs) separate Fly process.
5. Frontend: Next App Router, route groups (auth)/(ops)/(public), middleware.ts, @supabase/ssr. Client-side fetching via lib/api.ts to NEXT_PUBLIC_API_URL, 30s timeout, typed ApiError, hand-written lib/*-api.ts per domain.
6. CI/deploy (ci.yml): test job (corepack, Node 22.23, pnpm frozen lockfile, tsc, vitest, RLS replay in Docker Postgres, integration tests); migrate job on main against prod; deploy-backend: buildx on runner, push registry.fly.io, flyctl deploy --image, curl /health loop. fly.toml region sin, process groups app/worker/collab via tsx src/index.ts --role=X, concurrency soft 50 / hard 90. Vercel auto-deploys web.
7. Secrets (names): GH: FLY_API_TOKEN, DATABASE_URL, packages token. Fly: DATABASE_URL, MESSENGER_LISTEN_DATABASE_URL, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, CORS_ORIGIN, PASSPORT_*, DB_POOL_MAX/TX_MAX/QUEUE_MAX. Vercel: NEXT_PUBLIC_API_URL, NEXT_PUBLIC_SUPABASE_URL/ANON_KEY, NEXT_PUBLIC_PASSPORT_*.
8. Testing: Vitest per package; no standing test DB; rls-replay builds Postgres from journal and runs per-migration seed/assert SQL.
9. Do differently for Sail: prepare:false on 6543; 5432 session conn from day one (LISTEN, advisory locks, migrations); add staging DB (Supabase branch); no git-subdirectory private deps, publish packages; minimal pnpm overrides; compile to JS for prod instead of tsx; consider @hono/zod-openapi or Hono RPC instead of hand-written clients. Keep: per-request RLS txn with SET LOCAL ROLE, no PostgREST from browser, replay harness, migrate -> deploy -> /health, one image with role flags.
